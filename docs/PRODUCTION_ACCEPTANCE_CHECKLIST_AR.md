# قائمة قبول نسخة الإنتاج — Ghiyarak

هذه القائمة هي معيار قبول هندسي قبل اعتبار النسخة جاهزة للإطلاق التجاري. لا تكفي سلامة الواجهة وحدها؛ يجب تحقق السياسات، البيانات، القيود المحاسبية، وسلوك المنصات.

## 1. المنصات وتجربة الاستخدام

- Android يستخدم تجربة Material مناسبة للمس، مع أزرار ومساحات لمس واضحة، وتنقل سفلي عند الحاجة.
- Desktop و Web الواسع يستخدمان مساحة عمل احترافية مع شريط جانبي، جداول، مساحات أكبر، وسلوك موجه للفأرة ولوحة المفاتيح.
- لا توجد شاشة تتمدد فقط بدون إعادة تنظيم للعناصر.
- كل شاشة تدعم حالات التحميل، الخطأ، الفراغ، وإعادة المحاولة.
- التنقل العميق لا يكسر الروابط عند التحديث على Web.

## 2. الترجمة والاتجاه

- كل شاشة يجب أن تعمل بالعربية والإنجليزية.
- النصوص الجديدة لا تترك مفاتيح ترجمة ظاهرة للمستخدم.
- RTL/LTR يجب أن يكون تلقائيًا حسب اللغة.
- العملات، الأرقام، والتواريخ تعرض بصيغة محلية مناسبة.

## 3. الأمن والصلاحيات

- لا توجد صفحة إدارية أو مالية بدون `RequireAccess` أو Permission Guard.
- `admin_super` و `admin_operations` لهما تجاوز إشرافي مضبوط بدون تجاوز سياسات التدقيق.
- التاجر لا يدخل لوحة التاجر إلا إذا كانت مؤسسة MERCHANT معتمدة، باستثناء دخول الإدارة للإشراف.
- صاحب الورشة لا يدخل لوحة الورشة إلا إذا كانت مؤسسة WORKSHOP معتمدة، باستثناء دخول الإدارة للإشراف.
- الجلسات المنتهية أو التوكن غير الصالح يسببان خروجًا آمنًا.
- إعدادات الإنتاج لا تقبل أسرارًا افتراضية أو CORS محلي.

## 4. العمليات التجارية

- حالات الطلبات، الدفع، الاسترداد، التسوية، الشحن، والاعتماد تنتقل فقط عبر حالات مسموحة.
- كل تغيير حساس يجب أن يكتب Audit Log.
- كل عملية مالية لها Idempotency Key لمنع التكرار.
- لا يسمح باسترداد أو تسوية بمبلغ صفر أو سالب.
- لا يسمح برصيد مؤسسة سالب.
- لا يسمح بخلط عملات داخل رصيد مؤسسة واحد.

## 5. المحاسبة

- كل قيد محاسبي يتكون من سطرين على الأقل.
- كل سطر يكون مدينًا أو دائنًا فقط، وليس الاثنين، وليس صفرًا.
- مجموع المدين يساوي مجموع الدائن بعد التقريب.
- كل حركة مالية مرتبطة بقيد Journal Entry.
- الاسترداد يخصم من مستحقات المؤسسة ويرجع من نفس نوع أصل الدفع قدر الإمكان.
- التسوية تخصم من مستحقات المؤسسة وتخرج من الحساب البنكي.

## 6. التشغيل والنشر

- تشغيل `npm run build` للباكند بنجاح.
- تشغيل `npm run test` بنجاح.
- تشغيل `flutter analyze` بدون أخطاء.
- تشغيل التطبيق على Windows/Android/Web حسب الهدف.
- تشغيل Smoke Check على `/api/v1/health`.
- لا يتم النشر باستخدام `.env.example`.

## 7. حدود هذه النسخة

تم تقوية النسخة داخل الملفات المتاحة، لكن اعتماد الإنتاج النهائي يتطلب تشغيل الأوامر محليًا على جهاز التطوير لأن بيئة العمل الحالية لا تحتوي Flutter SDK ولا node_modules ولا اتصال قاعدة بيانات MySQL فعلي.
