# 02 — السيناريوهات التشغيلية النهائية

## 1. سيناريو الزائر Guest

1. يفتح التطبيق أو الويب.
2. يستطيع تصفح الصفحة الرئيسية.
3. يستطيع البحث عن قطع الغيار.
4. يستطيع مشاهدة تفاصيل المنتج والخدمات.
5. لا يستطيع الإضافة للسلة.
6. لا يستطيع إنشاء طلب.
7. لا يستطيع حجز خدمة.
8. عند محاولة عملية تحتاج حسابًا، يتم توجيهه للتسجيل أو الدخول.

## 2. سيناريو العميل Customer

1. يختار إنشاء حساب عميل.
2. يدخل الاسم ورقم الجوال أو الإيميل.
3. يستقبل OTP عبر القناة المختارة.
4. يتحقق من OTP.
5. يدخل مباشرة إلى حسابه.
6. يكمل الملف الشخصي.
7. يضيف العنوان.
8. يضيف المركبة.
9. يتصفح القطع والخدمات.
10. يضيف للسلة.
11. ينشئ الطلب.
12. يختار الدفع والتوصيل.
13. يتابع حالة الطلب.
14. يقيم المنتج أو الخدمة بعد اكتمال العملية.

## 3. سيناريو التاجر Merchant Owner

1. يختار إنشاء حساب تاجر.
2. يدخل بياناته الأساسية.
3. يتحقق OTP.
4. يضيف بيانات المتجر.
5. يضيف الفروع.
6. يضيف الحساب البنكي.
7. يرفع الوثائق.
8. يرسل طلب الاعتماد.
9. يرى صفحة انتظار المراجعة.
10. الإدارة توافق أو ترفض أو تطلب وثائق إضافية.
11. عند الموافقة تصله رسالة إيميل وإشعار داخل التطبيق.
12. تظهر له لوحة التاجر.
13. يستطيع إدارة المنتجات والمخزون والطلبات والموظفين والفروع.
14. يستطيع استيراد المنتجات من Excel.

## 4. سيناريو الورشة Workshop Owner

1. يختار إنشاء حساب ورشة.
2. يتحقق OTP.
3. يضيف بيانات الورشة.
4. يضيف الفروع.
5. يحدد الخدمات المقدمة.
6. يضيف ساعات العمل.
7. يرفع الوثائق.
8. يرسل طلب الاعتماد.
9. ينتظر موافقة الإدارة.
10. بعد الموافقة تظهر لوحة الورشة.
11. يستطيع إدارة الخدمات والحجوزات والفنيين والموظفين والفروع.
12. يستطيع استيراد منتجات/خدمات متعلقة بالورشة من Excel عندما يكون ذلك مسموحًا.

## 5. سيناريو موظف التاجر أو الورشة

1. المدير يضيف الموظف أو يرسل دعوة.
2. يحدد له الفرع أو كل الفروع.
3. يحدد له الصلاحيات.
4. الموظف يدخل ببياناته.
5. يتحقق OTP أو طريقة الدخول المعتمدة.
6. يرى فقط العمليات الممنوحة له.
7. كل عملية يقوم بها تسجل في Audit Logs.

## 6. سيناريو الإدارة Super Admin

1. يدخل المدير.
2. يرى لوحة التحكم.
3. يراجع طلبات التجار والورش والمستودعات.
4. يفتح الوثائق.
5. يقبل أو يرفض أو يطلب وثائق إضافية.
6. كل قرار يولد حدثًا.
7. النظام يرسل إشعارًا وإيميلًا.
8. النظام يسجل العملية في Audit Log.

## 7. سيناريو الدفع الحقيقي

1. العميل يختار طريقة الدفع.
2. النظام ينشئ Payment Intent.
3. إذا تحويل بنكي أو محفظة، يرفع العميل إثبات الدفع.
4. Finance Manager يراجع.
5. عند الموافقة يتم تأكيد الدفع.
6. عند بوابة دفع، ينتظر النظام Webhook موثق.
7. كل عملية مالية تولد قيودًا محاسبية متوازنة.
