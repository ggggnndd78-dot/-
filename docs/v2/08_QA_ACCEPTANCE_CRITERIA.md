# 08 — معايير القبول والاختبار

## 1. Auth + OTP

- طلب OTP عبر الإيميل يعمل.
- قناة SMS جاهزة للربط.
- OTP لا يخزن كنص صريح.
- OTP ينتهي بعد مدة محددة.
- لا يمكن استخدام OTP مرتين.
- تجاوز المحاولات يغلق الرمز.

## 2. Customer

- العميل يسجل ويدخل مباشرة.
- لا يحتاج موافقة الإدارة.
- تظهر له واجهات العميل فقط.

## 3. Merchant

- التاجر يسجل ويكمل بياناته.
- يرفع الوثائق.
- يبقى Pending قبل الموافقة.
- لا يستطيع إدارة المنتجات قبل الاعتماد.
- بعد الموافقة تصله إشعارات.
- بعد الموافقة تظهر له لوحة التاجر.

## 4. Workshop

- الورشة تسجل وتكمل بياناتها.
- تبقى Pending قبل الموافقة.
- بعد الموافقة تظهر لوحة الورشة.

## 5. Employees

- مدير التاجر أو الورشة يضيف موظفًا.
- الموظف يدخل بحسابه.
- يرى فقط الصلاحيات الممنوحة.
- لا يرى فروعًا غير مصرح بها.

## 6. Excel Import

- تحميل قالب Excel يعمل.
- رفع Excel يعمل.
- قراءة الأعمدة تعمل.
- قراءة الصفوف تعمل.
- الأخطاء تظهر قبل الحفظ.
- المنتجات الصحيحة تحفظ.
- المرفوضة لا تحفظ.

## 7. Admin Approval

- الإدارة ترى طلبات الاعتماد.
- الإدارة توافق أو ترفض.
- تصل إشعارات داخل التطبيق.
- يصل إيميل الموافقة أو الرفض.
- Audit Log يسجل العملية.

## 8. Finance

- لا يوجد دفع وهمي في منطق الإنتاج.
- كل دفع له Payment Intent.
- كل إثبات دفع له مراجعة مالية.
- كل قيد محاسبي متوازن.

## 9. Build Criteria

- Backend build success.
- Prisma generate success.
- Migrations success.
- Seed success.
- Swagger works.
- Flutter analyze success.
- Android run works.
- Web run works.
- Windows run works.
